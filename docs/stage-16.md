# Этап 16: связь коннектора — из общего модуля (0.11.4)

## Что изменилось

Для Claude и для человека — ничего. Внутри связь посредника `polka --mcp` с запущенной «Полкой» больше не лежит
в «Полке» своей копией, а берётся из общего модуля [kit](https://github.com/primus-fixer/kit) 0.6.0
(`kit_core::link`) — того же, на который переходит «Карман»:

- файл связи `claude.json` в папке данных: порт, ключ, процесс, версия;
- приём запросов посредника в запущенной «Полке» — только с 127.0.0.1, с проверкой ключа по одноразовым числам;
- посредник `polka --mcp`: протокол MCP по stdio, вызовы инструментов — запущенной «Полке»;
- запуск закрытой «Полки» из посредника на Windows.

## Как устроено

- `app/src-tauri/src/claude.rs` — `CONNECTOR`: имя и строка ключа связи (из `polka-core/src/mcp.rs`), переменная
  `POLKA_DIR`, название «Полка» и идентификатор `io.github.primusfixer.polka` (имя папки данных). Эти строки
  прежние и закреплены проверкой `connector_is_the_same_as_before_kit`. Инструменты, настройки коннектора
  и «Вернуть» остались в «Полке».
- `names.rs` — у названия появился род (`feminine: true`): «„Полка“ не запущена: откройте её…».
- Зависимости kit (Rust) — на коммит kit 0.6.0.

## Как проверено

- Настоящий посредник `polka --mcp` из «Полки» 0.11.3 и новый посредник спросили полку у новой «Полки»
  и получили записи из базы.
- Новый посредник подключился к запущенной «Полке» 0.11.3: она приняла доказательство ключа и ответила
  своим сообщением.
- В проверках kit: посредник в том виде, как он был до kit, говорит с новым приложением и наоборот; чужая
  программа на порту не получает ни ключа, ни запроса; приложение не выполняет запрос посредника без ключа.
